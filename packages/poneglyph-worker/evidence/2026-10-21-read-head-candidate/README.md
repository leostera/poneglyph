# Executed Datalog-capable read-scaling candidate

This evidence addresses the candidate-evaluation gap: it records an implementation of replicated exact-freshness read-head authorities, tests that candidate path with the independent oracle, and benchmarks it against zero heads. The candidate stores no graph facts; it replicates safe-vector metadata and may validate reuse of an exact completed Datalog row bag.

- Candidate implementation: historical experiment commit `3a567b3770408d441c9059de499157d5351eb149`, snapshot `a38765e44d95c92794b55a6b7d209ad0ac703349`. The last verified current baseline remains `529f4754489578610490f001c95a75f3f595d7c4`; the read-head implementation was not rebased onto it. It is kept isolated in the old experiment worktree/history, not added to canonical source.
- Independent oracle: the focused conformance oracle ran 10 cases warm and cold (20 case-phases), with a test-only facade adapter that joins and requires a live head before query cuts. For the 401-row multi-clause bag join, a replay was required to hit the read-head (`cacheHits=1`) with identical snapshot and byte-identical rows; after fact replacement and retraction, stale cache validation had to fall back before an exact fresh hit. Each returned bag was compared against the independent `Model`. Report: `conformance-focused-report.json`; harness sources and digests: `candidate-test-harness/`.
- Candidate-specific Worker suite: 27 passed, 0 failed (`read-head-worker-tests.txt`), including exact head-routing/freshness/fallback and RPC cases.
- Local benchmark: same local SQLite state compared 0 and 8 heads; 64 samples for each of point and five-clause combined queries per placement. Four rounds completed 64/64 with zero failures/retries. Point caller p50/p95/p99 was 8.98/10.38/10.42 ms (0 heads) vs 7.86/10.42/10.48 ms (8). Combined query was 37.47/39.09/39.15 ms vs 27.67/36.98/37.02 ms. Head mode reduced canonical read-cut calls from 64 to zero per round while every query was validated through a head. After a two-fact publication, 500/500 exact reads at observed concurrency 128 returned the new snapshot, all cache hits, with zero canonical read-cut calls; the single write took 39.7 ms. Raw observations, plans, source inputs, artifact hashes and report are in `local-run/`.
- Formal scope: archived candidate models show publication TLC for one and three heads, a routing-composition check (166,702 distinct states), and limited TLAPS lemmas. TLAPS was rerun: six local obligations proved and all three intended weakened-model controls rejected (TLAPM `901ae51`, Z3 4.8.9; no Isabelle certificate recheck). This is not a whole-protocol or implementation-refinement proof. TLC rerun could not start because the pinned `tla2tools.jar` is absent; the error, historical model summaries and source/tool hashes are retained here.

**Recommendation:** reject the read-head implementation for current selection; retain it as research. The local sample proves a reduction in read-cut RPCs but does not show meaningful point-query p99 gain, only a small combined-query p99 change, and adds synchronous publication work to writes. Its implementation snapshot predates the verified 529f475 baseline, so any reconsideration requires a port/re-proof and local mixed read/write/migration tests against the current protocol. No hosted performance inference is supported.
