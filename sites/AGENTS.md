# Sites

- Site applications belong under `sites/<hostname>/` and participate in the root Bun workspace and build/check/test gates. Keep one root `bun.lock`.
- Poneglyph remains a reusable database; applications own their HTTP/MCP surfaces. Do not add application-specific rules to canonical storage or fork its implementation.
- The playground composes `@leostera/poneglyph-mcp` with its dataset, ingress/rate limiter and a graph-scoped RPC binding to `@leostera/poneglyph-worker`. The private service owns canonical actor assembly and deployment-configured graph permissions. The site owns no database entrypoint or HTTP reader adapter; the source imports are not a published npm embedding contract.
- The playground at `onepiece.poneglyph.dev` is **public** (owner decision, 2026-10-25): no Cloudflare Access app, anonymous browser API and MCP. Reads use the read-only `playground` principal; `/api/facts` writes use `playground-writer` (write on `onepiece-wiki` only) under the shared `anonymous` author source. Every route is bounded by fail-closed native rate limits keyed by edge IP (MCP 30/min, API 120/min, writes 20/min, 25 facts per transaction); a missing or failing limiter never means unlimited. Same-origin JSON is still required for `/api/*`. Bulk imports remain loopback-operator-only and need explicit owner approval. See RFD0006 for history.
- `poneglyph.dev` is the static public landing page (Worker `poneglyph-www`, Kumo + Tailwind). It has no bindings and calls no Poneglyph API; it only links to the playground and repository. Keep its claims consistent with the README and RFDs.
- Default checks are offline, including a finite native integration with tiny synthetic facts. Never trigger deployment, account lookups, a wiki/corpus load or benchmarks through build/check/test.
- Read `docs/rfds/RFD0006-public-read-only-mcp-playground.md` for the application boundary and rollout limits. A built server, advertised schema, empty response or passing fixture does not prove that the One Piece corpus was loaded.

## poneglyph.lostera.me.cloudflare.dev

Temporary production benchmark target for the write path, on Leo's individual work account (`776b37f0f2474156eb01cf93c764b2e9`, cf profile `lostera`). It serves the plain graph HTTP API (`/v1/graphs/<graph>/{transactions,query,schema,entities}`) behind the account's Access app ("Just Me") and a bearer token (`PONEGLYPH_TOKEN` secret; local copy in `~/.config/poneglyph/lostera-bench-token`). Send `cf-access-token: $(cloudflared access token -app=https://poneglyph.lostera.me.cloudflare.dev)` and `authorization: Bearer <token>`. `POST /_bench/writes` runs edge load generators (`{generators, writers, seconds, factsPerTransaction, entitySpace, graph?}`).
