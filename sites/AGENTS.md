# Sites

- Site applications belong under `sites/<hostname>/` and participate in the root Bun workspace and build/check/test gates. Keep one root `bun.lock`.
- Poneglyph remains a reusable database; applications own their HTTP/MCP surfaces. Do not add application-specific rules to canonical storage or fork its implementation.
- The playground composes `@leostera/poneglyph-mcp` with its dataset, ingress/rate limiter and a graph-scoped RPC binding to `@leostera/poneglyph-worker`. The private service owns canonical actor assembly and deployment-configured graph permissions. The site owns no database entrypoint or HTTP reader adapter; the source imports are not a published npm embedding contract.
- The current public playground hostname, `onepiece.poneglyph.dev`, is protected by Worker-scoped Cloudflare Access for members of the owner's personal Cloudflare account. MCP remains read-only; its current graph contains six synthetic smoke-test facts and no imported wiki-corpus facts. A prior, superseded deployment had hosted receipts through `remainder90` ordinal 1794 (227,692 normalized page records / 1,096,908 base facts); those receipts are historical, not current graph state. The owner paused further base imports, ordinal 1795 onward was not imported to that earlier graph, and the separate 35,986-fact v5 semantic overlay remains local only. Separately, the 2026-10-17 MAV+ candidate was loaded into fresh private validation namespaces: 101,226 base facts / 11,014 page records, with one concurrent-read sample; this is not the public graph or a full load test. Its 1,428,969-fact continuation plan is pending explicit approval at SHA-256 `29becd5d4310224c59c3d6662d27fc7c3efa51eec5ab96805d0d254b97eab543`. Do not resume base or enrichment writes without an explicit renewed instruction and exact approved plan. Prior import authorization is limited to its hash-pinned plan and two-day window through a separate writer binding; it does not authorize arbitrary writes, derived enrichment imports, caller-selected backend/graph, admin/probe routes, unrelated large workloads, resource deletion or publication. Require runtime-verified `ctx.access` for the exact app audience, reject browser Origins, and enforce separate fail-closed admission before parsing/storage. No email PIN or public bypass policies; OPTIONS authentication is not bypassed. Generic MCP composition remains anonymous internally; local Access simulation is not a hosted membership-policy test. See RFD0006 for public deployment state, RFD0004 for the isolated candidate evidence, and the requirement to stop/reconcile any future unknown batch using its original identity.
- Default checks are offline, including a finite native integration with tiny synthetic facts. Never trigger deployment, account lookups, a wiki/corpus load or benchmarks through build/check/test.
- Read `docs/rfds/RFD0006-public-read-only-mcp-playground.md` for the application boundary and rollout limits. A built server, advertised schema, empty response or passing fixture does not prove that the One Piece corpus was loaded.
